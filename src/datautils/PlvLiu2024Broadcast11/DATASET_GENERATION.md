# Manuscript broadcast-11 dataset generation

This standalone package implements an inferred interpretation of the
manuscript's `29 nodes × 11 features` input. It has no import dependency on
`PlvLiu2024` and does not modify either dataset generated by that package
(`current_v1`, `manuscript_candidate_v2`) — the PLV/Hilbert connectivity math,
MAV/STD/PSD/betweenness feature calculations, persistent-homology topology
calculations, and the `PlvLiu2024GraphDataset` loading class are each copied
into this package (`connectivity.py`, `manuscript_features.py`,
`topology_features.py`, `source.py`, `graph.py`, `saved_dataset.py`) so this
package's behavior can never change as a side effect of an unrelated change
to `PlvLiu2024`. Keep these copies in sync by hand if the originals are ever
fixed.

For every EEG window, this package calculates PLV, a PLV>=0.3 binarized
adjacency, four electrode-specific features, and seven whole-graph
persistent-homology scalars, then defines the broadcast rule:

```text
[29, 4] local electrode features
    +
[7] whole-graph topology values repeated unchanged over 29 electrodes
    =
[29, 11] node-feature matrix
```

The columns are:

```text
MAV, STD, PSD, betweenness,
PersistenceEntropy_0,
landscape1_0, landscape1_1,
landscape2_0, landscape2_1,
betti_0, betti_1
```

## Gamma band

The manuscript defines its gamma band as **31–40 Hz** (verified against the
paper's text layer). This package's source is a dedicated preprocessed
directory filtered to exactly that band:

```text
data/moabb/Preprocessed-Gamma-31-40-MNE-liu2024-data
```

This is a separate directory from the 31–80 Hz source used by
`current_v1`/`manuscript_candidate_v2` (`data/moabb/Preprocessed-Gamma-MNE-liu2024-data`).
`Broadcast11Config.frequency_band_hz` and the PSD reducer's
`frequency_band_hz` both match this package's 31–40 Hz source.

Generate the complete dataset:

```bash
PYTHONPATH=/workspaces/EEG python \
  -m src.datautils.PlvLiu2024Broadcast11.generate_dataset
```

Verify it:

```bash
PYTHONPATH=/workspaces/EEG python \
  -m src.datautils.PlvLiu2024Broadcast11.verify_dataset
```

The output is:

```text
data/moabb/Graph-Gamma-PLV-Manuscript-31-40-11-liu2024-data
```

## Graph construction

`adjacency_matrices.npy` and the "betweenness" node feature are both derived
from `plv_matrices.npy` by thresholding at `Broadcast11Config.plv_threshold`
(default `0.3`) and binarizing to 0/1 — the manuscript's own ablation-selected
graph rule (Table 6), not a top-k union graph. Retained edges become exactly
`1.0` regardless of PLV magnitude, matching what the manuscript's own
"binarization strategies" description implies and what `EEGGCN1`
(`ourexperimentversionthree`) actually classifies on.

This graph is **not guaranteed connected**: a weakly-synchronized window can
leave a node with zero edges above threshold. That is expected, not an error
— roughly a quarter of graphs contain at least one isolated node at the
default threshold, and betweenness centrality is well-defined (`0`) for such
a node. `create_connectivity_components` validates this graph with
`require_no_isolated_nodes=False` for that reason.

`broadcast_source_features.npy` retains the original `[graphs, 7]` topology
values solely for auditing. The model loader does not expose it as graph-level
input. Base verification requires node columns 4–10 to equal those values
exactly for every one of the 29 nodes.

This representation follows the manuscript's stated input shape, but the
paper describes the topology descriptors as global properties and does not
document a node-specific mapping. The broadcast operation must therefore be
reported as an inferred reproduction choice.
